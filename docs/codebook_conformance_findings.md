# 碼冊一致性稽核報告（2026-08-14）

> **稽核對象**：`tcr_decoder` 的解碼／編碼邏輯
> **依據原文**：
> - 《癌症部位特定因子編碼手冊》民國114年12月修訂（`codebook_md/ssf_chunk_*.md`，原始 PDF 見 `docs/Cancer-SSF-Manual_Official-version_20251204_W.pdf`）
> - 《長表編碼手冊》（`codebook_md/longform_chunk_*.md`）
>
> **稽核方法**：對 11 個癌別 × SSF1–10 與結構欄位（AJCC／手術碼／區域淋巴結手術碼／
> EBRT／LN_POSITI）窮舉原始碼域（000–999、A00–A99、W/I/S 00–99、三字母碼）做
> decode → encode 還原比對，再把每個異常點回查手冊原文。
>
> **處理進度**：第一階段只修乳癌；第二階段（同日）續修攝護腺、子宮體、甲狀腺，
> 並把子宮頸／胃／肝／肺／結直腸的通用 sentinel 汙染清乾淨——目前 **9 個癌別**
> 已通過全碼域雙向驗證。尚未處理的項目見 B 節末。

## A. 乳癌（已修正）

| 項目 | 問題 | 處理 |
|---|---|---|
| SSF6 Nottingham | `encode` 產生 `'6'`，但官方編碼範圍是 030–090，`'6'` 申報會被退件 | 改為輸出 `'060'`；同時移除 decode 內非官方的 13–19 代碼 |
| SSF4／SSF5 哨兵淋巴結 | 兩欄共用同一組標籤，但手冊中 SSF4 的 000 =「未執行哨兵淋巴結手術」、SSF5 的 000 =「無淋巴結被侵犯」 | 標籤分開；`'000'` 也能正確解碼（原本只認 `'0'`） |
| SSF7 HER2 | 單碼 `'2'` 編回 `'2'`（非法碼）；單碼 `'0'` 編成 `'000'`（該碼另有「染色比例 0%」的特定意義） | 單碼一律正規化為官方 IHC 三碼 100/101/102/103 |
| SSF3／SSF4／SSF5／SSF6／SSF8／SSF9／SSF10 | 各欄位都被塞入 888「不適用（轉換）」，但 888 只在 SSF1／SSF2／SSF7 的官方範圍內 | 移除；非本欄位範圍的 sentinel 改解碼為 `Unlisted code 888`（可逆） |
| 全部 10 欄 | encode 未補零，輸出 `'70'`／`'5'`，但每個欄位長度都是 3 | 一律輸出官方寬度（`'070'`／`'005'`） |
| LN_POSITI（長表） | 95 與 98 解成同一句話；98 實際是「未移除或未檢出淋巴結組織」 | 95／97／98／99 四碼各自獨立標籤，2 碼寬度 |
| SSF8／SSF9 | 全流程 decode 會用輸入檔自帶的 `SSF8_decoded`／`SSF9_decoded` 覆寫，導致這兩欄無法反編碼 | 改用 profile 解碼器，乳癌 10 個 SSF 欄位全部可雙向 |
| Allred <1% 懸案 | `decode_er_pr` 註解與 `fable-opinion.md` 標記待人工核對 | 手冊 p.123 表格確認：proportion score 1（<1%）填共用碼 **120**，現行實作已正確 |
| **讀檔層丟失前置 0** | `read_excel` 只對 ID 欄位指定文字型別，其餘 `*_raw` 欄位被推斷成 int64，`'000'` 讀成 `0`。HER2 的 `000`（染色比例 0%）因此被當成舊制單碼 `0`（未描述染色比例＝100），代碼意義被改寫 | 所有 `*_raw` / `*_decoded` 欄位一律以文字讀入。此問題是由病例級驗證資料集抓出來的（欄位級測試抓不到，因為它不經過 Excel） |

**驗證資料集**：`python -m tcr_decoder --build-validation <輸出檔.xlsx>` 產生完整證據檔
（`tcr_decoder/validation.py`）：

- `Field_Coverage`：乳癌 10 欄**全部 1,187 個合法代碼**，逐碼列出碼冊中文定義、
  解碼後的臨床意義、反編碼結果、是否往返一致、寬度是否正確。
- `Case_Combinations` / `Case_Roundtrip`：以 pairwise（all-pairs）設計的 **542 個病例**，
  涵蓋任兩欄位取值的全部 **5,882 組**組合（100%），每個病例寫成真實登記檔案列，
  走完整解碼流程再反編碼，共 **5,420 筆**欄位比對。
- `Clinical_View`：每個病例的臨床解讀（含分子亞型與 NPI 分組），供人工核讀。
- 目前結果：**欄位級 0 失敗、病例級 0 失敗、寬度錯誤 0 筆**。

（10 欄全組合超過 10^20 種，無法窮舉；單碼已窮舉，組合層以兩兩交互作用全覆蓋。）

**驗證**：`tcr_decoder/code_ranges.py` 收錄乳癌 10 欄的完整官方編碼範圍，
`tests/test_codebook_conformance.py` 窮舉全部合法碼，證明
（1）每個合法碼都能解碼、（2）解碼在合法碼域上是單射（無兩碼共用標籤）、
（3）`encode(decode(code)) == code` 逐字相等、（4）encode 只會吐出合法且寬度正確的碼。
另有 300 筆合成乳癌全流程 `compare_roundtrip` → **0 筆不一致**。

## B. 其他癌別（2026-08-14 後續處理）

### 新增：頭頸部（含鼻咽 C11）

依手冊 pp.3-29 實作 SSF1-SSF10：頸部淋巴結大小、莢膜外侵犯、四組區域侵犯範圍
（三碼位置制：0=未侵犯、1=侵犯、8=跨區無法區分）、腫瘤深度、手術切緣距離、
臨床 ENE（三碼複合：綜合判定／影像／理學）、病理 ENE（距離編碼 101-120／221-298）。
適用部位 C00-C14、C30-C32、C76.0；**原本自創的 nasopharynx profile（EBV 效價等）已移除**。
`detect_cancer_group` 改為先比對 4 碼再比對 3 碼，才能只收 C76.0 而不誤收 C76.1-C76.8。

### 新增：食道／胰臟／卵巢／膀胱

- 食道（C15）SSF1-4：PET-CT、微創手術、前導療法病理反應、放療臨床反應

### 尚未處理

1. **淋巴瘤與白血病**：手冊 pp.193-221 有完整定義，但這兩組是依**組織型態（M-code）**
   而非原發部位判定（例如 M9650-9663 只登錄 SSF1-2、SSF7-10），而現行
   `detect_cancer_group` 只吃 TCODE1。要支援必須把形態碼一併納入判定，屬於結構性調整。
   另外 SSF1/SSF2 有 `8XX` 萬用碼、SSF10 是複合碼，碼表較複雜。
2. **長表結構欄位**：目前只驗證了 LN_POSITI 與 AJCC／手術碼／EBRT；區域淋巴結檢查數、
   期別、放療劑量等欄位尚未納入 `code_ranges.py` 的自動驗證。
